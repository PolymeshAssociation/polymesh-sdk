This guide describes **unreleased** changes since **v30.2.0** of `@polymeshassociation/polymesh-sdk`. These will be included in the next release.

---

## Overview

This release **drops all chain v7 support and backward-compatibility code**, now that the SDK only targets chain v8. `Context.isV7` and every v7/v8 branch are gone, along with every feature that only existed for v7 chains. This is a **breaking change** for any consumer still connecting to a v7 chain, or using one of the removed v7-only APIs below.

---

## Breaking changes

### Chain v7 is no longer supported

`SUPPORTED_SPEC_VERSION_RANGE` is narrowed from `'7.0 || 7.1 || 7.2 || 7.3 || 8.0'` to `'8.0'`. Connecting the SDK to a v7 chain now throws on initialization. `Context.isV7` and the internal `isV7Spec` util are removed.

### Removed entities/features (v7-only, no v8 equivalent)

- **`ChildIdentity` entity and all child-identity APIs**: `Identity.getChildIdentities`, `Identity.unlinkChild`, `Identity.isChild`, `Identities.createChild`, `Identities.createChildren`, `Identities.getChildIdentity`, the `createChildIdentity`/`createChildIdentities`/`unlinkChildIdentity` procedures, and `Context.getChildIdentity`. Removed types: `CreateChildIdentityParams`, `CreateChildIdentitiesParams`, `ChildKeyWithAuth`, `UnlinkChildParams`.
- **CDD claims**: `Claims.getCddClaims`, `Identity.hasValidCdd`, `CddClaim` handling, and `RoleType.CddProvider`/`isCddProviderRole` — superseded by the `DidRegistrar` role, which is now used unconditionally instead of the v7 `cddServiceProviders` pallet. `Identity.isCddProvider` is renamed to `Identity.isDidRegistrar` (see below).
- **`AccountManagement.subsidizeAccount`** — removed. The v7 flow created an `AddRelayerPayingKey` Authorization Request; use `AccountManagement.approveSubsidy` instead, which the beneficiary accepts via `AccountManagement.acceptSubsidy`.
- **Legacy relayer-paying-key authorization flow**: the `consumeAddRelayerPayingKeyAuthorization` procedure, `AuthorizationType.AddRelayerPayingKey`, and the `AddRelayerPayingKeyAuthorizationData`/`ConsumeAddRelayerPayingKeyAuthorizationParams` types are removed (the `OldAddRelayerPayingKey` type/flow remains). Receiving the removed authorization type now throws `NotSupported`, pointing consumers at `AccountManagement.approveSubsidy`.
- **Instruction affirmation withdrawal**: `InstructionAffirmationOperation.Withdraw`/`WithdrawAsMediator`, `Instruction.withdraw`/`withdrawAsMediator`, and the `WithdrawInstructionParams` type are removed — use `reject`/`rejectAsMediator` instead.
- **`Nft.controllerTransfer`'s deprecated `destinationPortfolio` param** — use `destination`.
- **`AcceptPrimaryKeyRotationParams.cddAuth`** and the associated CDD-authorization validation/consumption in `acceptPrimaryKeyRotation`.
- **`SetStakingControllerParams`** — `Staking.setController` is now a no-arg procedure since v8 always makes the stash its own controller. Likewise, **`BondPolyxParams.controller` is removed** — `bondPolyx` no longer accepts, validates, or sends a `controller` argument (the stash is always its own controller on v8, so the `RewardDestination::Controller` case can no longer occur; supplying a payee equal to the stash now resolves via the existing `stash` case).
- **`CddProviderRole`** type is removed.

### `Identity.isCddProvider` renamed to `Identity.isDidRegistrar`

The public method queried the v8 `didRegistrars` pallet already (the "CDD provider" role was superseded by the `DidRegistrar` role in v8), so it's renamed to match what it actually checks:

```typescript
// before
await identity.isCddProvider();
// after
await identity.isDidRegistrar();
```

### Docs and error messages

- `CreateMultiSigParams`'s note is updated from "Signer must be an Account as of v7" to "Signer must be an Account", and the corresponding `createMultiSig` validation error message drops the "as of v7" suffix.
- Several internal validations that check `Identity.exists()` (not CDD claim validity) had misleading CDD-era error messages; these are reworded to describe Identity existence instead. If your code matches on these error strings, update it:
  - `'Beneficiary Account does not have a valid CDD Claim'` → `'Beneficiary Account does not have an associated Identity'`
  - `'Subsidizer Account does not have a valid CDD Claim'` → `'Subsidizer Account does not have an associated Identity'`
  - `'Issuing Identity does not have a valid CDD claim'` → `'Issuing Identity does not exist'`
  - `'Issuer must be a CDD provider'` → `'Issuer must be a DID Registrar'`

### `registerIdentity`'s `createCdd`/`expiry` params are deprecated (no-op on v8)

As of chain v8, the underlying `cdd_register_did`/`cdd_register_did_with_cdd` extrinsics are deprecated and **no longer attach a `CustomerDueDiligence` claim** — they now behave identically to `identity.registerDid`. `Identities.registerIdentity` is marked `@deprecated`; the `createCdd`/`expiry` params no longer have any on-chain effect. Use `Identities.registerDid` (registrar-gated, added in v30.2.0) or `Identities.selfRegisterDid` (permissionless) instead.

### Simplified now-unconditional behavior (previously branched on `context.isV7`)

- `Context.getAccountBalance` only uses the v8 `FrameSystemAccountInfo` shape — the legacy `AccountInfo` assembly path is removed.
- `transferPolyx` always uses `balances.transferWithMemo` with an optional memo — v7's memo-less `balances.transfer` path is removed.
- `Instruction.generateOffChainAffirmationTransactionRaw`: `expiresAt` is now always mandatory, and the payload always includes the v8 receipt format.
- `Identity.checkRoleForDid`/`isGcMember` always query `didRegistrars.activeMembers` — the v7 `cddServiceProviders.activeMembers` fallback is gone.
- `registerDid` no longer needs to guard against v7 chains — the guard that threw `NotSupported` on v7 is removed since v7 is unsupported entirely.

## Migration steps

- Ensure the SDK connects only to **chain v8** nodes; v7 chains are no longer supported.
- Remove any usage of `ChildIdentity`/child-identity APIs (`Identities.createChild`, `createChildren`, `getChildIdentity`, and the `Identity.*` equivalents), CDD claim helpers, `RoleType.CddProvider`, `AccountManagement.subsidizeAccount` (use `approveSubsidy`/`acceptSubsidy`), `Instruction.withdraw`/`withdrawAsMediator` (use `reject`/`rejectAsMediator`), `Nft.controllerTransfer`'s `destinationPortfolio` param (use `destination`), `AcceptPrimaryKeyRotationParams.cddAuth`, and `SetStakingControllerParams`/`BondPolyxParams.controller` — these all throw type errors at compile time once upgraded, since the corresponding types are removed.
- Rename `Identity.isCddProvider()` calls to `Identity.isDidRegistrar()`.
- Handling of the legacy `AddRelayerPayingKey` authorization should be replaced with `AccountManagement.approveSubsidy`.
- Stop passing `controller` to `bondPolyx` — it's ignored/removed; the stash is always its own controller on v8.
- If relying on `registerIdentity`'s `createCdd`/`expiry` to attach a CDD claim, switch to whatever chain-side CDD issuance flow your deployment uses — these params no longer have any effect. Prefer `registerDid`/`selfRegisterDid` for new integrations.
- Update any code that matches on the error message strings listed above.
