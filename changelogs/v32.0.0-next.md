This guide describes **unreleased** changes for the next major version, **v32.0.0**, of `@polymeshassociation/polymesh-sdk`. If you're upgrading, start with the [Quick migration checklist](#quick-migration-checklist) below.

---

## Overview

v32.0.0 is a **major release**. Every middleware (SubQuery) query moves to the **redesigned SubQuery schema**, and the SDK requires a middleware that runs it. The redesign replaces string relations with id columns, stamps each row with the event that created and last updated it, splits POLYX history into one entry per side, and indexes events by what they involve rather than by argument position.

**Key themes in this release:**

- **Redesigned middleware required.** Queries against an older middleware fail.
- **Middleware enums follow the new schema.** OrderBy values and re-exported enums changed.
- **Settlement affirmations are per holder.** An Instruction lists one affirmation for every portfolio or Account on its legs, from the moment it is created.

---

## Prerequisites

### Supported middleware versions

The middleware must run the redesigned SubQuery schema (`polymesh-subquery`, `docs/architecture`, image `966b4a8c` or later). Methods that use the middleware fail against an older one, with GraphQL validation errors.

---

## Quick migration checklist

1. Upgrade the middleware to the redesigned SubQuery schema before upgrading the SDK.
2. Replace `CREATED_BLOCK_ID_*` OrderBy values with `CREATED_EVENT_ID_*`, and drop `EVENT_IDX_*` ones (see [Middleware enums](#1-middleware-enums-follow-the-new-schema)).
3. Replace `TickerExternalAgentActionsOrderBy` with `AssetAgentActionsOrderBy`.
4. Review code that reads `Instruction.getAffirmations()` (see [Affirmations are per holder](#3-instructiongetaffirmations-lists-every-holder)).

---

## Breaking changes

### 1. Middleware enums follow the new schema

The middleware types are regenerated from the redesigned schema. Every OrderBy enum the SDK accepts (`AssetHoldersOrderBy`, `AssetTransactionsOrderBy`, `AuthorizationsOrderBy`, `ClaimsOrderBy`, `InstructionsOrderBy`, and the others) loses its `CREATED_BLOCK_ID_*`, `UPDATED_BLOCK_ID_*` and `EVENT_IDX_*` values and gains `CREATED_EVENT_ID_*` and `UPDATED_EVENT_ID_*`. A `createdEventId` is `<block>/<event index>`, zero padded, so it orders rows by block and then by event, as the two old keys did together.

The `CREATED_AT_*` values the SDK adds to every OrderBy enum still order by creation.

### 2. Asset agent history uses the new agent tables

`identity.assetPermissions.getOperationHistory` takes `orderBy` as `AssetAgentActionsOrderBy` instead of `TickerExternalAgentActionsOrderBy`.

### 3. `Instruction.getAffirmations()` lists every holder

The middleware keeps one affirmation row for every portfolio and Account on an Instruction's legs, from the moment the Instruction is created, so the result now matches what the chain path has always returned:

- holders that have not affirmed yet are listed with `AffirmationStatus.Pending`;
- an Identity with several portfolios on the legs appears once per portfolio, and the new `portfolio` field says which;
- mediators are not listed; `getMediators()` returns them;
- a rejection is no longer an affirmation status. Use `getStatus()` to find whether the Instruction was rejected.

```typescript
const { data } = await instruction.getAffirmations();

data.forEach(({ party, portfolio, status }) => {
  // party: the Account, or the Identity owning `portfolio`
});
```

## Modified behavior

- **Off-chain legs.** An off-chain leg has no affirmation row of its own: it is affirmed once a receipt settles it. `getOffChainAffirmationForLeg` already reads it that way.
- **Portfolio movements.** `Portfolio.getTransactionHistory` and `identity.portfolios.getTransactionHistory` read movements from the middleware's Asset transactions. NFT movements between portfolios are now listed as NFT legs.
- **Leg addresses.** The `account` filter of `Portfolio.getTransactionHistory` now matches a settlement whose legs include that Account, instead of comparing it with the whole list of Accounts.

---

## Bug fixes

### `assetPermissions.enabledAt` returns this Identity's event

It used to return the event in which the Asset's most recent agent was added, whichever Identity that was. It now returns the event in which this Identity became an agent of the Asset.
